# HOI4 AI Commander

Внешний прототип агента для Hearts of Iron IV на Windows 11. Агент наблюдает клиентскую область игры, предлагает ограниченные игровые действия, проверяет цель перед нажатием и подтверждает результат по следующему скриншоту. Первая задача — мирная экономика Германии 1 января 1936 года: национальный фокус, исследование промышленной технологии и гражданская фабрика.

Сейчас полный цикл проверяется на **синтетических изображениях**, а ввод — на мок-устройстве. Эти изображения не являются скриншотами HOI4. Интеграция с реальной игрой, Win32, MSS, PyDirectInput и глобальной F10 в Windows требует отдельной проверки на Windows 11. Прототип не содержит универсального распознавания HOI4 и не может безопасно начать играть без ручной калибровки интерфейса.

## Установка

Нужны Python 3.12+ и Windows 11 для реального захвата и ввода. Для офлайн-тестов подходит Linux.

Из корня репозитория в PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,windows]"
python -m pytest
```

На Linux для мок-сценария:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
python -m pytest
```

## Сначала проверка без игры

```powershell
hoi4-commander input-test
hoi4-commander demo
hoi4-commander demo --mock-execute
hoi4-commander fixtures --output runtime/demo
hoi4-commander inspect --manifest runtime/demo/manifest.json --image runtime/demo/frame_00.png
hoi4-commander gui --config examples/settings.json
```

`input-test` проверяет движение мыши, клик и ESC исключительно через мок-ввод: настоящие устройства не затрагиваются. `demo` показывает первый план и цель в dry-run, не выполняя действия. `demo --mock-execute` проходит десять переходов синтетического сценария: только мок-клики переводят тестовую среду на следующий кадр. Это проверка логики цикла, а не доказательство работы с игрой.

`inspect` распознаёт сохранённый PNG по указанному манифесту и выводит найденные цели и неоднозначности. Команда не использует API и не выполняет ввод. Вместо синтетических файлов можно указать собственный скриншот и откалиброванный манифест; проверьте также кадры, на которых целевой элемент отсутствует.

Панель показывает кадр, целевую точку и объяснения. Кнопка остановки прерывает выполнение. По умолчанию реальный ввод и внешняя отправка скриншотов отключены. Если путь к манифесту не задан, используется синтетическая среда. Dry-run не симулирует успешное выполнение реальных действий и не объявляет сценарий пройденным.

Не переходите к реальной игре до успешного выполнения тестов мок-ввода, остановки и dry-run. В Windows дополнительно проверьте доступность глобальной F10; если её регистрация не удалась, агент должен запретить ввод.

## Калибровка реального интерфейса

Создайте локальный каталог `calibration/` — он исключён из Git. Скопируйте туда `examples/manifest.example.json` как `manifest.json`, а `examples/settings.json` как `settings.json`. В настройках укажите `template_manifest`: `calibration/manifest.json`. Относительные пути настроек считаются от текущего рабочего каталога; запускайте команды из корня репозитория. Пути PNG в манифесте считаются относительно самого манифеста.

Шаблоны — небольшие различимые фрагменты ваших собственных скриншотов при неизменных разрешении, масштабе интерфейса, DPI, языке, DLC и модификациях. Манифест-пример содержит только имена файлов, а не готовые игровые шаблоны. Поле `synthetic` для реального набора должно быть `false`; синтетический набор запрещён для реального ввода.

Подготовьте Германию, 1 января 1936 года, поставьте игру на паузу и вручную выведите её на передний план. Предпочтителен оконный режим или окно без рамок. Агент не переключает окна автоматически.

| Идентификатор | Что должно быть видно на шаблоне |
| --- | --- |
| `nation_germany` | Однозначный признак выбранной Германии |
| `date_1936_01_01` | Дата 1 января 1936 года |
| `game_paused` | Активная пауза |
| `focus_menu` | Кнопка открытия национальных фокусов |
| `focus_available` | Конкретный доступный экономический фокус |
| `focus_start` | Кнопка подтверждения выбранного фокуса |
| `focus_active` | Подтверждение, что выбранный фокус действительно начат |
| `research_menu` | Кнопка открытия исследований |
| `research_slot` | Конкретная свободная исследовательская ячейка |
| `technology_available` | Конкретная доступная промышленная технология |
| `technology_start` | Кнопка начала выбранного исследования |
| `research_active` | Подтверждение назначения этой технологии |
| `construction_menu` | Кнопка открытия строительства |
| `civilian_factory_tool` | Инструмент строительства гражданской фабрики |
| `building_state` | Однозначная доступная точка подходящего региона |
| `construction_queued` | Подтверждение новой гражданской фабрики в очереди |

Центр шаблона действия должен находиться внутри нужной кликабельной области. Цели не задаются фиксированными координатами: OpenCV находит шаблон в текущем кадре, затем координаты проверяются заново перед вводом. Два совпадения исключают цель из допустимых действий. Не используйте повторяющиеся иконки, однотонные области или общий заголовок окна вместо подтверждения результата.

Вы сами связываете `focus_available` с экономическим фокусом, `technology_available` — с промышленной технологией, а `building_state` — с доступным регионом. Прототип не читает текст дерева технологий, не вычисляет оптимальную стратегию и не распознаёт семантику региона. Шаблон `construction_queued` должен различать **новую гражданскую фабрику**, а не просто открытое меню очереди. Все три начальных признака — Германия, дата и пауза — должны оставаться различимыми на каждом проверяемом кадре. Если конкретная раскладка игры скрывает их при открытом меню, этот сценарий остановится и потребует изменения калибровки либо отдельной доработки распознавания.

Проверяйте каждый шаблон на сохранённых кадрах соответствующего перехода, включая отрицательные примеры. Пример манифеста — стартовая схема, а не проверенная калибровка вашей игры.

## Dry-run и реальный ввод

Сначала оставьте `mode` равным `dry_run`:

```powershell
hoi4-commander run --config calibration/settings.json
```

План и целевая точка должны соответствовать актуальному окну. В dry-run нет движения указателя, нажатий клавиш или кликов. Он останавливается до перехода интерфейса, который без ввода подтвердить невозможно.

Только после проверки тестов и dry-run разрешите доступ к игре:

```powershell
hoi4-commander consent --config calibration/settings.json
```

Интерактивная команда просит вручную ввести `РАЗРЕШАЮ` и сохраняет локальное согласие в `runtime/live-consent.json`. Оно разрешает игровой ввод, но **не** отправку скриншотов в API. Затем явно установите `mode`: `live` в локальной конфигурации и запустите `run`. В панели отдельная кнопка подтверждения показывает модальный запрос; переключатель реального ввода включается отдельно.

**F10 — глобальная экстренная остановка.** Она не требует фокуса панели. Перед каждым реальным запуском агент регистрирует F10 и, ещё не выполняя ввод, просит вручную вывести HOI4 на передний план и нажать F10 в течение 20 секунд. Это первое нажатие проверяет доставку горячей клавиши; после сообщения об успешной проверке все следующие нажатия F10 запрещают новые действия. Без успешной регистрации и проверки ввод не начинается. Остановка защёлкивается до завершения текущего запуска; повторный запуск — отдельное действие пользователя. Также доступна кнопка «Стоп» в панели. Проверка доставленного F10 сама по себе не доказывает работу реального PyDirectInput или всех условий игровой интеграции.

Перед каждым кликом проверяются актуальность кадра, процесс `hoi4.exe`, активное окно, клиентские границы и повторное совпадение цели. После движения указателя фокус проверяется ещё раз. Удерживаемые Shift/Ctrl/Alt/Win и кнопки мыши запрещают реальный клик, чтобы не изменить его смысл и не начать перетаскивание. Если окно изменилось, цель исчезла или переместилась, агент останавливается. Проверка результата повторяет только наблюдение с ограниченным временем ожидания; повторных кликов при неуспехе нет. Уже присутствовавший до действия маркер не считается подтверждением нового результата.

## Модель и смена провайдера

По умолчанию `provider.kind` равен `local`: используется детерминированный планировщик сценария без сети. Это позволяет проверять безопасность и цикл независимо от доступности API.

Для мультимодальной модели нужен HTTPS API, совместимый с `POST /chat/completions` и сообщениями с изображениями. В локальном файле настроек можно заменить адрес, модель и имя переменной окружения:

```json
{
  "kind": "openai_compatible",
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-4.1-mini",
  "api_key_env": "HOI4_MODEL_API_KEY",
  "timeout_seconds": 30
}
```

Установите переменную `HOI4_MODEL_API_KEY` вне репозитория через окружение процесса или безопасные настройки среды. Ключа в JSON быть не должно. Файл `.env` автоматически не загружается; `.env.example` содержит только имя необходимой переменной.

Для отправки изображений необходимо **отдельно и явно** установить `allow_external_screenshots`: `true` либо включить соответствующий переключатель в панели. При `false` сетевой провайдер отказывается от запроса; он не отправляет даже текст. В API уходит PNG клиентской области игры и краткий контекст шага, включая обнаруженные идентификаторы целей. Учитывайте политику хранения данных выбранного провайдера. Внешняя отправка не требуется для локального режима.

Поддерживается совместимый формат API, а не любой провайдер без адаптера. Для другого протокола реализуйте интерфейс `ModelProvider.choose(observation, step) -> Plan` и подключите его через `create_provider`. Модель не получает объект устройства ввода, окно Win32 или возможность исполнять код. Координаты, команды ОС и произвольные дополнительные поля отклоняются Pydantic. Для текущего сценария разрешён только клик по цели текущего шага; модель объясняет решение, но не расширяет список допустимых действий.

## Устройство проекта

| Компонент | Назначение |
| --- | --- |
| `observer` | MSS-захват клиентской области, OpenCV-поиск шаблонов, сохранённые кадры |
| `planner` | Связывает типизированный выбор провайдера с текущим шагом и кадром |
| `executor` | Мок-ввод и PyDirectInput, повторное наблюдение, проверки перед вводом |
| `verifier` | Новый скриншот и проверка ожидаемого изменения без повторного клика |
| `model_provider` | Локальный и сменный мультимодальный API-провайдер |
| `safety` | Согласие, свежесть кадра, границы, признаки сценария, остановка F10 |
| `journal` | Локальный журнал решений и диагностических событий JSONL |
| `controller` | Конечный цикл «наблюдение → план → действие → проверка» |
| `scenario` | Десять ограниченных шагов `germany_1936` |
| `gui` | Панель PySide6 с кадром, целью, объяснениями и остановкой |

Агент не меняет файлы HOI4, не читает память игры, не внедряет код в процесс и не выполняет военных операций. Имя процесса и границы окна получаются через публичные Win32 API.

## Журнал и диагностика

Журналы отдельных запусков сохраняются локально в `runtime/journal/` в формате JSONL. Они содержат планы, объяснения, результаты проверок и события ошибок. Для контролируемых ошибок сохраняются безопасное описание, тип и текущий шаг; для исключений сторонних SDK — только тип и общее сообщение без исходного текста. Рекурсивная фильтрация удаляет значения ключей API из вложенных полей журнала. Скриншоты и необработанные ответы API автоматически в журнал не записываются. Ключи API не сохраняются в конфигурации, исходниках и диагностике. Не добавляйте локальные ключи, согласия, игровые снимки и калибровку в коммиты.

При остановке выясните причину по журналу, проверьте паузу, дату, страну, передний план окна и совпадение масштаба шаблонов. Не снижайте порог до случайных совпадений, не отключайте проверки и не повторяйте реальный запуск вслепую.

## Реализованные этапы

| Этап | Результат |
| --- | --- |
| 1. Структура, конфигурация, типы и тесты | Пакет Python, строгие Pydantic-схемы, безопасные настройки |
| 2. Захват и тест ввода | MSS/Win32-адаптеры и диагностика мыши/клавиатуры на мок-устройстве |
| 3. Распознавание сохранённых кадров | OpenCV-шаблоны, локальный `inspect`, синтетические PNG и проверка неоднозначности |
| 4. Основной цикл | Наблюдение, планирование, ограниченный ввод, подтверждение на новом кадре |
| 5. Отдельный провайдер | Локальная стратегия и сменный мультимодальный HTTPS API с явным разрешением |
| 6. Сценарий и панель | Десять мирных шагов `germany_1936`, PySide6, показ цели и объяснений |
| 7. Тесты, ошибки и документация | Unit-тесты, мок-ввод, безопасный JSONL-журнал и инструкции калибровки |

Эти этапы реализованы на уровне прототипа. Приёмка управления настоящей HOI4 на Windows 11 остаётся **непроверенной**; для неё нужны игра, пользовательская калибровка и отдельный интеграционный прогон.

## Что проверяют тесты и что остаётся проверить

`python -m pytest` проверяет типизированные действия, ограничения провайдера, запрет отправки без разрешения, распознавание сохранённых синтетических кадров, неоднозначные цели, мок-ввод, остановку и цикл сценария. Актуальный результат прогона смотрите в выводе тестового запуска.

До практического использования остаются интеграционные проверки на Windows 11: DPI и координаты MSS/Win32 при ваших мониторах, определение окна HOI4, PyDirectInput, глобальная F10 во время ввода, смена фокуса пользователем, анимации интерфейса, реальные подтверждения фокуса/исследования/очереди и совместимость конкретного API. Наличие Windows-зависимостей или успешный синтетический сценарий этих проверок не заменяют.

Прототип намеренно останавливается на неопределённости. Военные операции, продолжительная кампания, автоматическая калибровка, OCR и выбор стратегии по всему дереву фокусов в первую версию не входят.
